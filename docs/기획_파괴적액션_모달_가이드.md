# 파괴적 액션(Destructive Action) 모달 통일 가이드

> 작성일: 2026-03-18 | 우선순위: C | 대상: 프론트엔드 개발자

## 1. 현황 분석

### 현재 구현 방식 (3가지 혼재)

| 방식 | 사용처 | 건수 | 문제점 |
|------|--------|------|--------|
| `confirmDialog()` 함수 | 대부분의 삭제/해제 | 21건 | ✅ 통일됨 |
| HTML 하드코딩 모달 | 발주처 삭제, 팀 삭제 | 2건 | ⚠️ 별도 구현 |
| `confirm()` 네이티브 | Figma URL 해제 | 1건 | ❌ 스타일 불일치 |

**총 24건의 파괴적 액션 모달 존재**

## 2. 통일 원칙

### 2-1. 단일 구현체 사용
- **모든 파괴적 액션은 `confirmDialog()` 함수를 사용**한다
- HTML 하드코딩 모달 → `confirmDialog()`로 마이그레이션
- 네이티브 `confirm()` → `confirmDialog()`로 교체

### 2-2. 위험도 분류 (3단계)

| 위험도 | 색상 | 조건 | 예시 |
|--------|------|------|------|
| 🔴 Critical | `bg-red-600` | 되돌릴 수 없는 데이터 삭제 | 팀 삭제, 프로젝트 삭제 |
| 🟠 High | `bg-red-600` | 데이터 삭제 (복구 어려움) | 업무/문서/게시글/댓글 삭제 |
| 🟡 Medium | `bg-yellow-600` | 연결 해제/비활성화 (재설정 가능) | 캘린더 해제, Figma 해제, 포털 비활성화 |

## 3. 모달 구조 규격

### 3-1. 기본 구조
```
┌─────────────────────────────────┐
│  ⚠️ [아이콘]                      │
│                                 │
│  [제목]                          │
│  [본문 설명]                      │
│                                 │
│  (확인 입력 필드 — Critical만)      │
│                                 │
│       [취소]     [확인 버튼]       │
└─────────────────────────────────┘
```

### 3-2. 스타일 규격

| 요소 | 클래스 |
|------|--------|
| 배경 오버레이 | `bg-black bg-opacity-50 z-[110]` |
| 모달 박스 | `max-w-sm bg-white dark:bg-gray-800 rounded-xl p-6 shadow-xl` |
| 아이콘 (Critical) | `w-12 h-12 text-red-500 mx-auto mb-4` — ExclamationTriangle |
| 아이콘 (High) | `w-12 h-12 text-red-400 mx-auto mb-4` — TrashIcon |
| 아이콘 (Medium) | `w-12 h-12 text-yellow-500 mx-auto mb-4` — ExclamationCircle |
| 제목 | `text-lg font-semibold text-gray-900 dark:text-white text-center` |
| 본문 | `text-sm text-gray-500 dark:text-gray-400 text-center mt-2` |
| 취소 버튼 | `px-4 py-2 border border-gray-300 dark:border-gray-600 rounded-lg text-gray-700 dark:text-gray-300 hover:bg-gray-50 dark:hover:bg-gray-700` |
| 확인 버튼 (삭제) | `px-4 py-2 bg-red-600 text-white rounded-lg hover:bg-red-700` |
| 확인 버튼 (해제) | `px-4 py-2 bg-yellow-600 text-white rounded-lg hover:bg-yellow-700` |

## 4. 전체 모달 문구 통일표

### 4-1. Critical (확인 입력 필요)

| 대상 | 제목 | 본문 | 확인 입력 | 확인 버튼 |
|------|------|------|----------|---------|
| 팀 삭제 | 팀 삭제 | 이 작업은 되돌릴 수 없습니다. 모든 팀 데이터가 영구 삭제됩니다. 확인하려면 팀 이름을 입력하세요. | `{팀 이름}` 입력 | 영구 삭제 |

### 4-2. High (단순 확인)

| 대상 | 제목 | 본문 | 확인 버튼 |
|------|------|------|---------|
| 발주처 삭제 | 발주처 삭제 | "{이름}"을(를) 삭제하시겠습니까? 관련 데이터도 함께 삭제됩니다. | 삭제 |
| 프로젝트 삭제 | 프로젝트 삭제 | 이 프로젝트를 삭제하시겠습니까? 관련 업무와 문서도 함께 삭제됩니다. | 삭제 |
| 업무 삭제 | 업무 삭제 | 이 업무를 삭제하시겠습니까? | 삭제 |
| 업무 일괄 삭제 | 일괄 삭제 | {N}건의 업무를 삭제하시겠습니까? 이 작업은 되돌릴 수 없습니다. | 삭제 |
| 문서 삭제 | 문서 삭제 | 이 문서를 삭제하시겠습니까? 모든 버전과 댓글도 함께 삭제됩니다. | 삭제 |
| 댓글 삭제 | 댓글 삭제 | 이 댓글을 삭제하시겠습니까? | 삭제 |
| 게시글 삭제 | 게시글 삭제 | 이 게시글을 삭제하시겠습니까? 댓글도 함께 삭제됩니다. | 삭제 |
| 보고서 삭제 | 보고서 삭제 | 이 보고서를 삭제하시겠습니까? | 삭제 |
| 템플릿 삭제 | 템플릿 삭제 | "{이름}" 템플릿을 삭제하시겠습니까? | 삭제 |
| 반복 업무 삭제 | 반복 업무 삭제 | "{이름}" 반복 업무를 삭제하시겠습니까? | 삭제 |
| 멤버 제거 | 멤버 제거 | {이름}님을 팀에서 제거하시겠습니까? | 제거 |
| 프로필 이미지 삭제 | 이미지 삭제 | 프로필 이미지를 삭제하시겠습니까? | 삭제 |
| 초대 취소 | 초대 취소 | 이 초대를 취소하시겠습니까? | 취소 |

### 4-3. Medium (해제/비활성화)

| 대상 | 제목 | 본문 | 확인 버튼 |
|------|------|------|---------|
| 캘린더 연동 해제 | 연동 해제 | 캘린더 연동을 해제하시겠습니까? 언제든 다시 연동할 수 있습니다. | 해제 |
| Figma URL 해제 | Figma 연결 해제 | 이 Figma 파일 연결을 해제하시겠습니까? 언제든 다시 연결할 수 있습니다. | 해제 |
| 포털 링크 비활성화 | 포털 링크 비활성화 | 포털 링크를 비활성화하시겠습니까? 발주처가 더 이상 접근할 수 없습니다. | 비활성화 |

## 5. 문구 작성 규칙

| 규칙 | 예시 |
|------|------|
| 제목은 **동작 + 대상** 형태 | "업무 삭제", "멤버 제거" |
| 본문은 **의문문**으로 시작 | "이 업무를 삭제하시겠습니까?" |
| 부작용이 있으면 **두 번째 문장으로 안내** | "관련 업무와 문서도 함께 삭제됩니다." |
| 복구 가능하면 **안심 문구 추가** | "언제든 다시 연동할 수 있습니다." |
| 확인 버튼 텍스트는 **동작 동사** | 삭제, 제거, 해제, 비활성화, 취소 |
| "확인", "네", "예" 같은 **모호한 버튼명 금지** | ❌ "확인" → ✅ "삭제" |
