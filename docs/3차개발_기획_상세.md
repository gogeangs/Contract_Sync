### 1.3 시스템 프롬프트 (백엔드 전달용)

```
당신은 Contract Sync의 내부 업무 어시스턴트입니다.
이름은 "CS 어시스턴트"이며, 회사 내부 직원들의 업무를 보조합니다.

## 역할
- Contract Sync 시스템의 데이터를 조회하고 요약하여 답변합니다.
- 읽기 전용입니다. 데이터를 생성, 수정, 삭제할 수 없습니다.
- 시스템에 존재하는 데이터만 기반으로 답변하며, 추측하지 않습니다.

## 응답 규칙
1. 한국어로 답변합니다. 사용자가 영어로 질문하면 영어로 답변합니다.
2. 간결하고 명확하게 답변합니다. 불필요한 서론을 붙이지 않습니다.
3. 숫자, 날짜, 상태 등 구체적인 정보를 포함합니다.
4. 3개 이상의 항목은 목록 또는 표로 정리합니다.
5. 데이터가 없으면 "해당 데이터가 없습니다"라고 안내합니다.
6. 모르는 내용은 "확인할 수 없습니다"라고 솔직하게 답변합니다.

## 사용자 정보
- 이름: {user_name}
- 역할: {user_role}
- 소속 팀: {team_names}

## 권한
{permission_context}

## 금지 행동
- 시스템에 없는 데이터를 만들어내지 않습니다.
- 개인정보(비밀번호, 토큰 등)를 노출하지 않습니다.
- 데이터 수정/삭제 방법을 안내하지 않습니다 (읽기 전용).
- 회사 외부 정보에 대해 답변하지 않습니다.
- 다른 직원의 급여, 인사 정보에 대해 답변하지 않습니다.
- 시스템 내부 구조(DB 스키마, API 엔드포인트 등)를 노출하지 않습니다.
```

### 1.4 금지 행동 상세

| # | 금지 행동 | 대응 방식 |

| 5 | 외부 정보 질의 | "Contract Sync 내부 데이터만 조회 가능합니다" 응답 |

### 3.2 권한 판별 로직

```
1. 사용자의 team_member.role 조회
2. role == "owner" → 관리자 (수금/매출 데이터 접근 가능)
3. role != "owner" → 일반 직원 (수금/매출 데이터 차단)
4. 팀 미소속 사용자 → 개인 데이터만 접근 (team_id=None)
```

### 3.3 챗봇 권한 컨텍스트 (시스템 프롬프트에 주입)

**일반 직원용:**
```
조회 가능: 발주처, 프로젝트, 업무, 댓글, 활동 로그, 보고서, 팀 업무량, 본인 알림
조회 불가: 수금/결제 정보, 매출/미수금 통계, 견적서 금액
- 수금 관련 질문 시: "수금 정보는 관리자만 조회할 수 있습니다."
```

**관리자(대표)용:**
```
조회 가능: 모든 데이터 (수금/매출/미수금 포함)
- 제한 없음
```

### 3.4 데이터 필터링 규칙

| 시나리오 | 처리 방식 |
|---------|----------|
| 일반 직원이 "미수금 알려줘" | "수금 정보는 관리자만 조회할 수 있습니다." 응답 |
| 일반 직원이 "프로젝트 계약 금액" | 계약 금액은 프로젝트 정보에 포함 → **차단** (금액 관련 전체 차단) |
| 관리자가 "이번 달 매출" | PaymentSchedule에서 paid 상태 합산하여 응답 |
| 타 팀 데이터 질의 | "해당 팀의 데이터에 접근할 수 없습니다." 응답 |

### 3.5 백엔드 구현 가이드

```python
# chatbot_service.py 에서 권한 컨텍스트 생성
async def build_permission_context(db, user) -> str:
    team_ids = await get_user_team_ids(db, user.id)
    is_admin = False
    for tid in team_ids:
        member = await db.execute(
            select(TeamMember).where(
                TeamMember.team_id == tid,
                TeamMember.user_id == user.id,
                TeamMember.role == "owner"
            )
        )
        if member.scalar_one_or_none():
            is_admin = True
            break

    if is_admin:
        return "조회 가능: 모든 데이터 (수금/매출/미수금 포함)"
    else:
        return (
            "조회 가능: 발주처, 프로젝트, 업무, 댓글, 활동 로그, 보고서, 팀 업무량, 본인 알림\n"
            "조회 불가: 수금/결제 정보, 매출/미수금 통계, 견적서 금액\n"
            "수금 관련 질문 시: '수금 정보는 관리자만 조회할 수 있습니다.'로 응답"
        )
```

## P-4. Figma 연동 프로세스 기획

### 4.1 연결 방식

| 항목 | 설계 |
|------|------|
| 연결 단위 | 프로젝트 1개 ↔ Figma 파일 N개 |
| 저장 위치 | Project 테이블에 `figma_urls` 필드 추가 (JSON 배열) |
| 입력 방식 | 프로젝트 상세 → Figma 탭 → URL 입력 필드 |
| URL 형식 | `figma.com/design/:fileKey/:fileName` |
| 검증 | URL 형식 검증 + Figma API로 파일 접근 가능 여부 확인 |

### 4.2 Figma 토큰 관리

| 항목 | 설계 |
|------|------|
| 토큰 종류 | Figma Personal Access Token |
| 저장 위치 | 환경변수 `FIGMA_ACCESS_TOKEN` (팀 공용) |
| 대안 | 향후 OAuth2로 확장 가능 (사용자별 토큰) |
| 권한 범위 | 파일 읽기 전용 (File:Read) |

### 4.3 조회 시나리오

| # | 시나리오 | 트리거 | 동작 |
|---|---------|--------|------|
| 1 | Figma 시안 미리보기 | 프로젝트 상세 → Figma 탭 클릭 | 연결된 Figma 파일 목록 + 썸네일 표시 |
| 2 | 시안 스크린샷 조회 | Figma 파일 클릭 → 페이지 선택 | 선택한 페이지의 스크린샷 (PNG) 표시 |
| 3 | 챗봇에서 시안 조회 | "A 프로젝트 시안 보여줘" | 해당 프로젝트의 Figma 파일 목록 + 최신 스크린샷 반환 |
| 4 | 시안 변경 감지 | 스케줄러 (1시간 간격) | Figma 파일 `lastModified` 비교 → 변경 시 팀 알림 |
| 5 | 디자인 메타데이터 | Figma 탭 상세 | 페이지 수, 컴포넌트 수, 최종 수정일 표시 |

### 4.4 Figma 탭 UI 구성

```
[프로젝트 상세 페이지]
  ├── 개요 탭
  ├── 업무 탭
  ├── 문서 탭
  ├── 댓글 탭
  └── ★ Figma 탭 (신규)
        ├── [+ Figma 파일 연결] 버튼
        ├── 연결된 파일 목록
        │     ├── 파일명 (Figma 링크)
        │     ├── 썸네일 이미지
        │     ├── 최종 수정일
        │     └── [삭제] 버튼
        └── 선택한 파일 상세
              ├── 페이지 목록 (탭 형태)
              └── 선택 페이지 스크린샷
```

### 4.5 Figma 변경 알림

| 항목 | 설계 |
|------|------|
| 감지 주기 | 1시간 (설정 변경 가능) |
| 감지 방식 | Figma API `GET /v1/files/:key` → `lastModified` 비교 |
| 알림 대상 | 해당 프로젝트의 팀 멤버 전원 |
| 알림 타입 | `figma_update` (Notification.type에 추가) |
| 알림 메시지 | "[프로젝트명] Figma 시안이 업데이트되었습니다" |
| 알림 링크 | 프로젝트 상세 → Figma 탭으로 이동 |

### 5.3 피드백 요청 DB 스키마 (신규)

```sql
CREATE TABLE feedback_requests (
    id INTEGER PRIMARY KEY,
    project_id INTEGER NOT NULL REFERENCES projects(id),
    sender_id INTEGER NOT NULL REFERENCES users(id),     -- PM
    recipient_email TEXT NOT NULL,                         -- 고객 이메일
    subject TEXT NOT NULL,                                 -- 요청 제목
    message TEXT,                                          -- 요청 내용
    attachments JSON DEFAULT '[]',                         -- 첨부 파일 경로
    figma_url TEXT,                                        -- Figma 시안 링크
    feedback_token TEXT UNIQUE NOT NULL,                    -- 고유 토큰 (64자)
    feedback_deadline DATE,                                -- 응답 기한
    status TEXT DEFAULT 'sent',                            -- sent/viewed/responded/expired
    viewed_at TIMESTAMP,                                   -- 고객 열람 시각
    responded_at TIMESTAMP,                                -- 고객 응답 시각
    reminder_count INTEGER DEFAULT 0,                      -- 리마인더 발송 횟수
    last_reminder_at TIMESTAMP,                            -- 마지막 리마인더 시각
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_feedback_requests_project ON feedback_requests(project_id);
CREATE INDEX idx_feedback_requests_token ON feedback_requests(feedback_token);
CREATE INDEX idx_feedback_requests_status ON feedback_requests(status);
```

## P-7. 리마인더 정책 정의

### 7.1 자동 리마인더 규칙

| 항목 | 정책 |
|------|------|
| **1차 리마인더** | 요청 후 **3 영업일** 미응답 시 자동 발송 |
| **2차 리마인더** | 1차 후 **3 영업일** 추가 미응답 시 자동 발송 |
| **3차 리마인더** | 2차 후 **5 영업일** 추가 미응답 시 자동 발송 |
| **최대 발송 횟수** | **3회** (이후 PM에게 "수동 연락 필요" 알림) |
| **발송 시각** | 오전 10:00 (KST) — 업무 시간 내 수신 유도 |
| **영업일 계산** | 월~금 (공휴일 미적용, 추후 공휴일 DB 추가 가능) |

### 7.2 리마인더 발송 스케줄 예시

```
Day 0 (월)  — 피드백 요청 이메일 발송
Day 3 (목)  — 1차 리마인더 (미응답 시)
Day 6 (화)  — 2차 리마인더 (미응답 시) ※ 주말 제외
Day 11 (화) — 3차 리마인더 (미응답 시) ※ 주말 제외
Day 11+     — PM에게 알림: "고객 미응답 — 직접 연락 필요"
```

### 7.3 리마인더 중단 조건

| 조건 | 동작 |
|------|------|
| 고객이 피드백 제출 | 즉시 리마인더 중단 |
| 고객이 포털 열람 (viewed) | 리마인더 계속 (열람 ≠ 응답) |
| PM이 수동 중단 | "리마인더 중단" 버튼 → 중단 |
| 피드백 요청 만료 | 토큰 만료 시 자동 중단 |
| 최대 횟수 초과 (3회) | 자동 중단 + PM 알림 |

| 이벤트 | 알림 내용 | 알림 타입 |
|--------|----------|----------|
| 리마인더 발송 시 | "{프로젝트} 리마인더 {N}차 발송됨" | `feedback_reminder` |
| 최대 횟수 도달 | "{프로젝트} 고객 미응답 — 직접 연락 필요" | `feedback_escalation` |

### 7.5 스케줄러 구현 가이드

```python
# scheduler_service.py 에 추가
async def check_feedback_reminders(db):
    """미응답 피드백 요청에 대해 리마인더 발송"""
    now = datetime.now(KST)

    # 영업일 계산 (월~금)
    if now.weekday() >= 5:  # 토, 일
        return

    # 발송 시각: 오전 10시
    if now.hour != 10:
        return

    pending = await db.execute(
        select(FeedbackRequest).where(
            FeedbackRequest.status == "sent",
            FeedbackRequest.reminder_count < 3
        )
    )

    for req in pending.scalars():
        business_days = count_business_days(req.last_reminder_at or req.created_at, now)
        threshold = 3 if req.reminder_count < 2 else 5

        if business_days >= threshold:
            await send_feedback_reminder(req)
            req.reminder_count += 1
            req.last_reminder_at = now

    await db.commit()
```
