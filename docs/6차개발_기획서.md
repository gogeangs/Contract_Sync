## Phase 2: AI 어시스턴트 1단계 + 출퇴근 연동

### 2-1. 오늘의 브리핑

**목적**: 로그인 시 AI가 사용자의 오늘 상황을 자동 요약하여 대시보드 최상단에 표시

**표시 항목 및 우선순위**

| 순위 | 항목 | 데이터 소스 | 조건 | 문구 예시 |
|------|------|-----------|------|----------|
| 1 | 오늘 마감 업무 | tasks (due_date = today) | 있을 때만 | "오늘 마감 업무 {n}건" |
| 2 | 내일 마감 업무 | tasks (due_date = tomorrow) | 있을 때만 | "내일 마감 업무 {n}건" |
| 3 | 미확인 피드백 | feedback_responses (unread) | 있을 때만 | "고객 피드백 {n}건 미확인" |
| 4 | 읽지 않은 채팅 | room_messages (unread) | 있을 때만 | "채팅 {n}건 읽지 않음" |
| 5 | 3일간 미업데이트 업무 | tasks (updated_at < 3일 전) | 있을 때만 | "진행 중 업무 {n}건 3일간 변동 없음" |
| 6 | 출근 미기록 | attendance (today, 없음) | 업무 시간일 때 | "오늘 출근 기록이 없어요" |

**UI 구조**

```
┌──────────────────────────────────────────────────────┐
│  👋 좋은 아침, {사용자명}님!                             │
│                                                       │
│  🔴 오늘 마감 업무 2건                    [확인하기]     │
│  🟡 고객 피드백 1건 미확인                 [확인하기]     │
│  💬 채팅 5건 읽지 않음                    [읽기]        │
│  ⏰ 오늘 출근 기록이 없어요               [업무 시작하기]  │
│                                                       │
│  항목 없을 때: "오늘은 특별한 알림이 없어요! 좋은 하루 되세요" │
└──────────────────────────────────────────────────────┘
```

**인사말 규칙**

| 시간대 | 인사말 |
|--------|--------|
| 06:00~11:59 | 좋은 아침 |
| 12:00~17:59 | 좋은 오후 |
| 18:00~05:59 | 좋은 저녁 |

**액션 버튼 동작**

| 항목 | 버튼 | 동작 |
|------|------|------|
| 마감 업무 | 확인하기 | `#/my-tasks` 이동 |
| 미확인 피드백 | 확인하기 | `#/feedback-requests` 이동 |
| 읽지 않은 채팅 | 읽기 | `#/chat` 이동 |
| 출근 미기록 | 업무 시작하기 | POST /attendance/check-in + 출근 토스트 |

**API 요구사항**
- `GET /api/v1/dashboard/briefing` — 위 항목을 한 번에 조회하여 반환

### 2-2. 상황 인식 챗봇

**목적**: 챗봇이 사용자가 현재 보고 있는 화면의 맥락을 자동으로 파악하여 관련 응답 제공

**화면별 맥락 전달 정의**

| 화면 (currentPage) | 전달할 맥락 | 챗봇이 아는 정보 |
|-------------------|-----------|----------------|
| `dashboard` | 없음 (전체) | 전체 통계, 최근 업무 |
| `projectDetail` | `project_id` | 프로젝트명, 진행률, 업무 목록, 발주처 |
| `tasks` | `project_id` (선택됨) | 업무 목록, 필터 상태 |
| `clientDetail` | `client_id` | 발주처명, 연락처, 프로젝트 목록 |
| `boards` | `team_id`, `board_id` | 게시판명, 최근 게시글 |
| `chat` | `room_id` | 채팅방명, 참여자 |
| `attendance` | `team_id` | 출퇴근 상태, 월별 기록 |
| `settings` | 없음 | 설정 항목 안내 |
| `payments` | 없음 | 수금 현황 |
| `reports` | 없음 | 보고서 목록 |

**챗봇 API 요청 변경**

```json
// 현재
POST /api/v1/chatbot/message
{ "message": "..." }

// 변경
POST /api/v1/chatbot/message
{
  "message": "...",
  "context": {
    "page": "projectDetail",
    "params": { "id": 5 }
  }
}
```

**화면별 응답 예시**

| 화면 | 사용자 질문 | AI 응답 |
|------|-----------|---------|
| 프로젝트 상세 | "남은 업무 뭐야?" | "A사 웹사이트 프로젝트의 미완료 업무는 3건입니다: 디자인 시안, API 연동, QA" |
| 프로젝트 상세 | "진행률 어때?" | "현재 진행률 75%입니다. 8건 중 6건 완료, 2건 진행중" |
| 업무 목록 | "높음 우선순위만 보여줘" | "높음 우선순위 업무 2건: 디자인 시안(D-1), DB 설계(D-3)" |
| 발주처 상세 | "연락처 알려줘" | "A사 담당자: 김철수 (010-1234-5678, kim@a.com)" |
| 대시보드 | "이번 주 완료율 어때?" | "이번 주 완료 업무 5건, 완료율 62%입니다" |

**맥락 없는 질문 처리**
- 화면과 무관한 질문은 기존처럼 전체 서비스 맥락으로 응답

## Phase 3: AI 어시스턴트 2단계 + 퇴근 연동

### 3-1. 능동적 알림

**목적**: AI가 사용자의 업무 상황을 모니터링하고, 조치가 필요한 시점에 먼저 알림

**알림 트리거 정의**

| # | 트리거 | 조건 | 검사 주기 | 문구 | 액션 버튼 |
|---|--------|------|----------|------|----------|
| 1 | 마감 D-1 | due_date = 내일, status ≠ completed | 매일 09:00 | "{업무명} 업무가 내일 마감입니다" | [확인하기] [완료 처리] |
| 2 | 마감 당일 | due_date = 오늘, status ≠ completed | 매일 09:00 | "{업무명} 업무가 오늘 마감입니다" | [확인하기] [완료 처리] |
| 3 | 마감 초과 | due_date < 오늘, status ≠ completed | 매일 09:00 | "{업무명} 업무가 {n}일 지연되었습니다" | [확인하기] [마감 연장] |
| 4 | 3일간 미업데이트 | status = in_progress, updated_at < 3일 전 | 매일 10:00 | "{업무명} 업무가 3일간 변동 없습니다" | [상태 업데이트] |
| 5 | 피드백 도착 | feedback_response 신규 | 실시간 | "고객 피드백이 도착했습니다" | [확인하기] |
| 6 | 출근 미기록 | 오늘 attendance 없음, 09:30 이후 | 평일 09:30 | "오늘 출근 기록이 없어요" | [업무 시작하기] |
| 7 | 퇴근 시간 | 근무 정책 check_out 시간 도래 | 평일 정책 시간 | "오늘의 업무를 정리할까요?" | [업무 보고 작성] |
| 8 | 주간 보고 | 매주 금요일 | 금 16:00 | "이번 주 주간 보고서를 작성할까요?" | [작성하기] |
| 9 | 읽지 않은 채팅 | unread_count > 0, 30분 경과 | 30분마다 | "읽지 않은 채팅 {n}건이 있습니다" | [확인하기] |
| 10 | 초대 미수락 | pending_invite > 3일 | 매일 10:00 | "팀 초대가 3일간 대기 중입니다" | [확인하기] |

**액션 버튼 동작 방식**

| 버튼 | 동작 |
|------|------|
| [확인하기] | 해당 페이지로 이동 |
| [완료 처리] | PATCH /tasks/{id} status=completed → 토스트 |
| [마감 연장] | 날짜 선택 모달 → PATCH /tasks/{id} due_date |
| [상태 업데이트] | 상태 선택 드롭다운 → PATCH /tasks/{id} status |
| [업무 시작하기] | POST /attendance/check-in → 토스트 |
| [업무 보고 작성] | 업무 보고 모달 열기 |
| [작성하기] | `#/reports` 이동 |

**중복 알림 방지**
- 동일 트리거 + 동일 대상은 24시간 내 1회만 발송
- 사용자가 액션을 완료하면 관련 알림 자동 읽음 처리

### 3-3. 퇴근 — AI 업무 보고 + 자동 퇴근

**흐름**

```
퇴근 시간대 AI 알림:
  "오늘 활동 내역을 정리했어요. 확인하고 퇴근할까요?"

  ┌─────────────────────────────────┐
  │  오늘의 업무 보고                  │
  │                                  │
  │  ✅ 디자인 시안 v2 완료           │
  │  🔄 API 연동 70% → 90%          │
  │  💬 A사 피드백 회신 완료           │
  │  + 메모 추가 (선택)               │
  │                                  │
  │  [수정하기]  [제출 및 퇴근]        │
  └─────────────────────────────────┘

  [제출 및 퇴근] → 업무 보고 저장 + 퇴근 시간 자동 기록
```

**AI 자동 요약 데이터 소스**
- tasks: 오늘 상태 변경된 업무
- board_posts: 오늘 작성한 게시글
- room_messages: 오늘 발송한 채팅
- feedback_responses: 오늘 처리한 피드백

## Phase 4: AI 어시스턴트 3단계 (자연어 명령)

### 4-1. 자연어 명령 실행

**목적**: 챗봇에 자연어로 말하면 AI가 의도를 파악하고 기존 API를 호출하여 업무 처리

**지원 명령어 목록**

| 분류 | 사용자 입력 예시 | 의도(action) | API | 필수 파라미터 |
|------|----------------|-------------|-----|-------------|
| **업무 생성** | "내일까지 디자인 시안 업무 만들어" | create_task | POST /tasks | task_name, due_date |
| **업무 생성** | "A 프로젝트에 QA 업무 추가해줘" | create_task | POST /tasks | task_name, project_id |
| **업무 수정** | "이 업무 마감일 금요일로 변경해" | update_task | PATCH /tasks/{id} | due_date |
| **업무 수정** | "김철수에게 업무 배정해" | update_task | PATCH /tasks/{id} | assignee_id |
| **업무 완료** | "디자인 시안 완료 처리해" | complete_task | PATCH /tasks/{id} | status=completed |
| **프로젝트 조회** | "A 프로젝트 진행률 어때?" | query_project | GET /projects/{id} | project_id |
| **업무 조회** | "내 업무 보여줘" | navigate | — | → #/my-tasks 이동 |
| **업무 조회** | "오늘 마감 업무 뭐야?" | query_tasks | GET /tasks?due_date=today | due_date |
| **수금 조회** | "이번 달 수금 현황 보여줘" | navigate | — | → #/payments 이동 |
| **발주처 조회** | "A사 연락처 알려줘" | query_client | GET /clients/{id} | client_id |
| **발주처 생성** | "B사 발주처 등록해줘" | create_client | POST /clients | name |
| **출근** | "출근" | check_in | POST /attendance/check-in | team_id |
| **퇴근** | "퇴근" | check_out | POST /attendance/check-out | team_id |
| **보고서** | "주간 보고서 만들어줘" | create_report | POST /reports/generate | type=weekly |
| **채팅** | "김철수에게 메시지 보내줘" | send_message | POST /chat/rooms/{id}/messages | content |

### 4-2. Gemini Function Calling 정의

```json
{
  "functions": [
    {
      "name": "create_task",
      "description": "새 업무를 생성합니다",
      "parameters": {
        "task_name": { "type": "string", "required": true },
        "project_id": { "type": "integer" },
        "due_date": { "type": "string", "format": "YYYY-MM-DD" },
        "priority": { "type": "string", "enum": ["높음", "보통", "낮음"] },
        "assignee_name": { "type": "string" }
      }
    },
    {
      "name": "update_task",
      "description": "기존 업무를 수정합니다",
      "parameters": {
        "task_name_or_id": { "type": "string", "required": true },
        "due_date": { "type": "string" },
        "status": { "type": "string" },
        "priority": { "type": "string" },
```

### 4-3. 확인 UI 흐름

```
[데이터 조회 (읽기)] → 즉시 응답, 확인 불필요

[데이터 변경 (쓰기)] → 확인 필요:

  AI: "다음 업무를 생성할까요?"
      ┌────────────────────────────────┐
      │  업무명: 디자인 시안              │
      │  프로젝트: A사 웹사이트           │
      │  마감일: 2026-03-17             │
      │  우선순위: 보통                   │
      │                                │
      │  [생성하기]  [수정하기]  [취소]    │
      └────────────────────────────────┘

  [생성하기] → API 호출 → "업무가 생성되었어요! [업무 보기]"
  [수정하기] → "어떤 항목을 수정할까요?" → 대화 계속
  [취소] → "취소했습니다"
```

### 4-4. 파라미터 자동 추론 규칙

| 파라미터 | 추론 방법 |
|---------|----------|
| project_id | 현재 보고 있는 프로젝트 / "A 프로젝트" → 이름으로 검색 |
| due_date | "내일" → +1일, "금요일" → 다음 금요일, "3일 후" → +3일 |
| assignee | "김철수" → 팀 멤버에서 이름 검색 |
| team_id | 현재 선택된 팀 |
| priority | 미지정 시 "보통" 기본값 |

### 4-5. 에러 처리

| 상황 | AI 응답 |
|------|---------|
| 필수 파라미터 부족 | "업무명을 알려주세요" (추가 질문) |
| 권한 없음 | "이 작업은 관리자만 할 수 있어요" |
| 대상 못 찾음 | "'B 프로젝트'를 찾을 수 없어요. 혹시 'B사 리뉴얼'을 말씀하시나요?" (유사 검색) |
| API 실패 | "처리 중 오류가 발생했어요. 다시 시도해주세요" |
