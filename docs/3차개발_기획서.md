## 1. 배경 및 목표

### 1.1 회사 현황

| 구분 | 내용 |
|------|------|

| 비즈니스 3 | nopibox.com — 무인매장관리서비스 (별도 운영) |

### 1.2 외주 업무 흐름

| 단계 | 담당 | 소요 기간 | 비고 |
|------|------|----------|------|
| 1. 문의 접수 | PM | - | 고객 요구사항 파악 |

| 3. 계약 체결 | PM | - | 계약서 작성 |
| 4. 기획 | PM | 1~2일 | **PM 최대 병목** |
| 5. 디자인 | 디자이너 | 3~4일 | 1명이 5~6건 동시 → **디자이너 병목** |

- **프로젝트 1건**: 약 10~12 영업일 (실제 3~4주 — 고객 피드백 대기 포함)
- **동시 진행**: 5~6건
- **CS 매니저**: nopibox.com 전담 (외주 업무 미참여)

### 1.3 주요 병목

| 병목 | 원인 | 영향 |
|------|------|------|
| **디자이너 과부하** | 1명이 5~6건 동시 진행 | 에셋 정리 부족 → 개발자 시안 학습 비용 증가 |
| **고객 응답 지연** | F&B 프랜차이즈(오프라인 중심) 고객 특성 | 프로젝트 전체 일정 지연 |
| **정보 전달 손실** | 기획→디자인→개발 간 수작업 전달 | 소통 비용 증가 |
| **Figma MCP 한계** | 시안 재현도가 낮음 | 코드 자동 생성 어려움 |

### 1.4 주 고객 특성

- **대상**: F&B 프랜차이즈 브랜드 (가맹본부)
- **랜딩페이지 목적**: 예비 가맹점주 모집
- **커뮤니케이션**: 카카오톡 중심, 응답 대기 시간 길음
- **정보량**: 고객마다 전달 정보량 천차만별 (섹션 수 유동적)

### 1.5 최종 목표

> **AI 에이전트를 하나의 가상 직원으로 관리하여, 각 직원의 업무를 부분적으로 경감시키는 것**

- 현재: 사람이 90% 이상 업무 수행
- 목표: AI가 점진적으로 업무 비중을 확대 (읽기 → 제안 → 실행 → 자율)

## 3. AI 에이전트 — 가상 직원 로드맵

### 3.1 단계별 확장 계획

| 단계 | 버전 | AI 역할 | 예시 |
|------|------|---------|------|
| **v1 (3차 개발)** | 읽기 전용 어시스턴트 | 데이터 조회 + 요약 | "프로젝트 현황 알려줘" |
| v2 | 제안형 | 추천 + 사용자 승인 | "이 업무 마감 임박 → 우선순위 변경할까요?" |
| v3 | 실행형 | 직접 업무 수행 | 보고서 작성, 상태 변경, 일정 조율 |
| v4 | 자율형 (가상 직원) | 업무 할당 → 판단 → 처리 → 보고 | AI에게 업무 배정하면 스스로 완수 |

### 3.2 v1부터 반영할 설계 원칙

- AI 에이전트를 **User 테이블에 등록** (type: `ai_agent`)
- 대화 이력을 **별도 테이블에 저장** (추후 학습/개선용)
- 업무 할당 시 **assignee로 AI 선택 가능**한 구조 (v1에서는 비활성)

## 4. MCP 연동

### 4.1 1순위: Figma MCP

| 항목 | 내용 |
|------|------|
| 용도 | 디자인 시안 조회, 스크린샷 가져오기 |
| 활용 | "A 프로젝트 피그마 시안 현황", 시안→코드 가이드 생성 |
| 비고 | 현재 피그마 MCP 한계(시안 재현도 낮음)가 있으나, 조회/요약 용도로는 활용 가능 |

### 4.2 MCP 자동 추천 기능

사용자의 **업무 패턴을 AI가 분석**하여 외부 MCP를 추천하고 연결하는 기능:

- 영상 관련 업무 증가 → "YouTube/영상 편집 MCP를 추천합니다"
- Figma 링크 공유 빈번 → "Figma MCP를 연결하세요"
- Google Drive 파일 참조 많음 → "Google Drive MCP를 추천합니다"

### 4.3 연동 후보 목록

| MCP | 용도 | 우선순위 |
|-----|------|---------|
| **Figma** | 디자인 시안 조회 | **1순위** |
| Google Calendar | 일정 관리 | 2순위 |
| Google Drive | 문서 관리 | 2순위 |
| GitHub | 개발 현황 (커밋, PR) | 3순위 |
| Gmail | 이메일 조회/요약 | 3순위 |
| Slack/Discord | 팀 커뮤니케이션 | 검토 |

## 5. 고객 피드백 시스템

### 5.1 [필수] 방식 A — 자체 포털 + 이메일

```
PM이 시안 완성
  → Contract Sync에서 "피드백 요청" 버튼 클릭
  → 이메일 자동 발송: "시안 확인해주세요" + 고객 포털 링크
  → 고객이 포털에서 시안 확인 + 피드백 입력
  → 피드백이 댓글/Task로 자동 등록
  → N일 미응답 시 리마인더 자동 발송
```

| 항목 | 내용 |
|------|------|
| 추가 비용 | 없음 |
| 개발 난이도 | 낮음 (기존 포털 + 이메일 기능 활용) |
| 효과 | 고객 피드백 구조화 + PM 수작업 감소 |

### 5.2 [선택] 방식 B — 카카오 알림톡 + 포털 링크

> 방식 A 운영 후 효과 검증 → 확장 여부 결정

```
PM이 시안 완성
  → Contract Sync에서 "피드백 요청" 버튼 클릭
  → 알림톡 자동 발송: "OO 브랜드 시안이 완성되었습니다. [확인하기]"
  → 고객이 카카오톡에서 링크 클릭 → 포털에서 피드백 입력
  → Contract Sync에 자동 반영
```

| 항목 | 내용 |
|------|------|
| 추가 비용 | 카카오 비즈니스 딜러사 계약 (월 기본료 + 건당 비용) |
| 개발 난이도 | 중간 |
| 효과 | 이메일보다 높은 응답률 (카카오톡 알림이 즉시 노출) |
| 전제 조건 | 방식 A 운영 경험 + 딜러사 계약 완료 |

### 5.3 카카오 비즈니스 API 조사 결과

| 기능 | 설명 | 활용 가능성 |
|------|------|------------|
| 알림톡 | 정보성 메시지 발송 | 시안 완성 알림, 피드백 요청, 리마인더 |
| 친구톡 | 마케팅 메시지 (채널 친구 대상) | 해당 없음 |
| 상담톡 | 1:1 실시간 채팅 상담 | 향후 확장 (v2+) |
| 챗봇 | 자동 응답 시나리오 | 향후 확장 (v3+) |

- **주의**: 공식 딜러사(비즈고, 인포뱅크 등)를 통해서만 API 연동 가능
