### #1. 활동 로그 페이지

#### 1-1. 개요
- 목표: 팀원/프로젝트의 모든 활동을 시간순으로 확인하여 "지금 뭐 하고 있어?" 질문 제거
- 경로: `#/activity`
- 사이드바 메뉴에 "활동 로그" 항목 추가 (위치: 업무 아래)

#### 1-2. 화면 구성

```
+------------------------------------------------------+
| 활동 로그                                    [필터 v] |
+------------------------------------------------------+
| 필터 바 (접이식)                                      |
| [프로젝트 선택 v] [팀 선택 v] [활동 타입 v]           |
+------------------------------------------------------+
| 타임라인                                              |
|                                                      |
| 오늘 ──────────────────────────────────────          |
|  09:30  홍길동  '웹사이트 리뉴얼' 업무 상태를          |
|         완료로 변경했습니다                            |
|  09:15  김영희  '계약서 검토' 업무에 댓글을            |
|         남겼습니다 "수정사항 반영했습니다..."           |
|                                                      |
| 어제 ──────────────────────────────────────          |
|  18:00  이철수  '디자인 시안' 프로젝트를               |
|         생성했습니다                                  |
|                                                      |
| [더 보기]                                            |
+------------------------------------------------------+
```

#### 1-3. 상세 요구사항

**필터**
| 필터 | 소스 | 동작 |
|------|------|------|
| 프로젝트 | 사용자 접근 가능 프로젝트 목록 | `?project_id=N` |
| 팀 | `GET /teams` 내 팀 목록 | `?team_id=N` |
| 활동 타입 | 프론트 정의 (전체/생성/수정/댓글/상태변경/삭제) | `action` 필드 기준 프론트 필터 |

**타임라인 항목 구성**
- 아바타 (user_picture 또는 이니셜)
- 사용자 이름 (user_name)
- 활동 설명: `action` + `target_type` + `target_name` 조합으로 한국어 문장 생성
- 상세 내용 (detail) — 있으면 회색 글씨로 1줄 표시, 최대 100자 + "..."
- 시간 표시: 오늘이면 "HH:mm", 그 외 "M월 D일 HH:mm"

**활동 메시지 매핑**
| action | target_type | 메시지 |
|--------|-------------|--------|
| create | project | '{target_name}' 프로젝트를 생성했습니다 |
| create | task | '{target_name}' 업무를 생성했습니다 |
| update | project | '{target_name}' 프로젝트를 수정했습니다 |
| status_change | task | '{target_name}' 업무 상태를 변경했습니다 |
| comment | task | '{target_name}' 업무에 댓글을 남겼습니다 |
| comment | project | '{target_name}' 프로젝트에 댓글을 남겼습니다 |
| assign | task | '{target_name}' 업무를 할당했습니다 |
| delete | task | '{target_name}' 업무를 삭제했습니다 |
| invite | member | '{target_name}'님을 팀에 초대했습니다 |
| remove | member | '{target_name}'님을 팀에서 제거했습니다 |
| 그 외 | * | '{target_name}'에 대해 {action} 작업을 수행했습니다 |

**페이지네이션**
- 방식: "더 보기" 버튼 (무한스크롤 아님)
- 1회 로드: 30건 (API 기본값)
- "더 보기" 클릭 시 page+1 로드, 기존 목록 아래에 append
- 전체 로드 완료 시 "더 보기" 버튼 숨김

**날짜 그룹핑**
- 같은 날짜의 활동은 날짜 구분선 아래에 묶음
- 구분선 텍스트: "오늘", "어제", "M월 D일 (요일)"

#### 1-4. API 연동

| 동작 | API | 파라미터 |
|------|-----|----------|
| 목록 조회 | `GET /activity` | `project_id`, `team_id`, `page`, `size` |

- 기존 API 수정 불필요 (응답 형식 그대로 사용)
- 프론트에서 `action` 값 기준 필터링 (활동 타입 필터)

#### 1-5. 프론트엔드 구현

- Alpine.js 함수: `activityPage()`
- `x-data` 속성: `items[]`, `page`, `totalItems`, `loading`, `filters`
- `index.html`에 `#/activity` 라우팅 + 페이지 섹션 추가
- 사이드바 nav에 "활동 로그" 링크 추가

#### 1-6. 예외 처리
- 활동 0건: "아직 활동이 없습니다. 프로젝트나 업무를 생성해보세요." 빈 상태 표시

- API 에러: 토스트로 에러 메시지 표시

#### 2-3. 매출 추이 차트

**데이터**
- API: `GET /dashboard/revenue`
- 응답: `{ months: ["10월", "11월", ...], amounts: [5000000, 3200000, ...] }`

**차트 사양**
- 방식: CSS 기반 라인 차트 (외부 라이브러리 없이 구현)

- Y축: 금액 (만원 단위 표시, 예: "500만")
- 데이터 포인트에 hover 시 정확한 금액 툴팁

**CSS 기반 구현 방식 (라이브러리 없이)**
- 컨테이너 높이 200px, 각 월을 균등 분할
- 각 금액을 최대값 대비 %로 변환하여 높이 결정
- `<div>` 바 또는 SVG polyline으로 시각화
- 금액이 0인 경우 바 높이 최소 2px

#### 2-4. 팀 워크로드 시각화

### #5. 업무 상태 변경 자동 알림

#### 5-1. 개요
- 목표: 업무 담당자가 상태를 변경하면 관련자에게 자동 알림 → "지금 진행 상황이 어때?" 제거
- 변경 파일: `app/api/endpoints/tasks.py`

#### 5-2. 알림 발생 규칙

| 상태 변경 | 수신 대상 | 알림 메시지 |
|-----------|-----------|-------------|
| * → 진행중 | 프로젝트 관리자 | "{사용자}님이 '{업무명}' 작업을 시작했습니다" |
| * → 완료 | 프로젝트 관리자 + 같은 프로젝트 팀원 | "{사용자}님이 '{업무명}'을 완료했습니다" |
| * → 보류 | 프로젝트 관리자 | "{사용자}님이 '{업무명}'을 보류 처리했습니다" |
| 담당자 변경 | 새 담당자 | "{사용자}님이 '{업무명}' 업무를 할당했습니다" |

**수신 대상 정의**
- 프로젝트 관리자: `projects.user_id` (프로젝트 생성자)
- 같은 프로젝트 팀원: `team_members` WHERE `team_id = project.team_id` (팀 프로젝트인 경우)
- 본인 제외: 상태를 변경한 사람에게는 알림 미발송

#### 5-3. 백엔드 구현

**tasks.py PATCH 엔드포인트 수정**
```python
# 상태 변경 감지
old_status = task.status
# ... 기존 업데이트 로직 ...
new_status = task.status

if old_status != new_status:
    # 알림 생성
    await _create_status_change_notifications(db, task, user, old_status, new_status)
```

**알림 생성 함수**
- `_create_status_change_notifications(db, task, user, old_status, new_status)`
- Notification 레코드 생성:
  - `type`: "status_change"
  - `title`: 위 규칙표의 메시지
  - `link`: `{"project_id": N, "task_id": N}`

#### 5-4. 알림 타입 정의
- `type = "status_change"`
- 기존 Notification 모델의 type 필드에 추가 (컬럼 변경 불필요, String 타입)

#### 5-5. 예외 처리
- 개인 프로젝트(team_id=null): 프로젝트 생성자에게만 알림
- 프로젝트 없는 업무(project_id=null): 알림 미생성
- 같은 상태로 변경 시: 알림 미생성

### #3. 알림 센터 개선

#### 3-1. 개요
- 목표: 알림을 체계적으로 관리하여 중요한 변경 사항을 놓치지 않게 함
- 기존: 헤더 벨 아이콘 드롭다운에 목록만 표시
- 개선: 드롭다운 확장 + 전체 알림 페이지(`#/notifications`)

#### 3-2. 드롭다운 개선

```
+------------------------------------+
| 알림                [모두 읽음]     |
+------------------------------------+
| [전체] [댓글] [멘션] [업무] [팀]    |  <-- 타입 필터 탭
+------------------------------------+
| * 홍길동님이 댓글을 남겼습니다       |
|   웹사이트 리뉴얼 프로젝트에...     |
|   2분 전                           |
|------------------------------------+
| * 김영희님이 업무를 완료했습니다     |
|   계약서 검토                       |
|   1시간 전                          |
+------------------------------------+
|       [전체 알림 보기 >]            |
+------------------------------------+
```

**타입 필터 탭**
| 탭 | 포함 type 값 |
|----|-------------|
| 전체 | 모두 |
| 댓글 | comment |
| 멘션 | mention |
| 업무 | status_change, assign, deadline |
| 팀 | team_invite |

**각 알림 항목**
- 읽지 않은 알림: 좌측 파란 점 표시 + 배경색 약간 진하게
- 클릭 시: 읽음 처리 (`PATCH /notifications/{id}/read`) + link 파싱하여 해당 페이지로 이동
- 삭제: 항목에 hover 시 우측에 X 버튼 → `DELETE /notifications/{id}`
- "모두 읽음" 버튼: `PATCH /notifications/read-all`

#### 3-3. 전체 알림 페이지 (#/notifications)

```
+------------------------------------------------------+
| 알림 센터                                             |
+------------------------------------------------------+
| [전체] [댓글] [멘션] [업무] [팀]    [읽지않은것만 v]   |
+------------------------------------------------------+
| (드롭다운과 동일한 목록, 페이지네이션 추가)            |
|                                                      |
| [이전] 1 / 5 [다음]                                  |
+------------------------------------------------------+
```

- 페이지네이션: 20건씩
- `?unread_only=true` 파라미터로 읽지 않은 것만 필터링
- 프론트에서 타입 필터 적용 (API 호출 없이 클라이언트 필터)

#### 3-4. API 연동

| 동작 | API | 비고 |
|------|-----|------|
| 목록 | `GET /notifications?page=1&size=20&unread_only=false` | 기존 API |
| 읽음 처리 | `PATCH /notifications/{id}/read` | 기존 API |

#### 3-5. 프론트엔드 구현

### #4. 실시간 알림 (SSE)

#### 4-1. 개요
- 목표: 새 알림 발생 시 페이지 새로고침 없이 즉시 브라우저에 반영
- 방식: **SSE (Server-Sent Events)** 선택
  - WebSocket 대비 구현 단순, 서버→클라이언트 단방향이면 충분
  - Railway 배포 환경에서 WebSocket보다 안정적

#### 4-2. 백엔드 — SSE 엔드포인트

**새 파일: `app/api/endpoints/sse.py`**

```
GET /sse/notifications
```

- 인증: 쿠키 기반 세션 토큰 확인
- 연결 유지: `text/event-stream` Content-Type
- 이벤트 형식:
  ```
  event: notification
  data: {"id": 123, "type": "comment", "title": "...", "message": "..."}

  event: heartbeat
  data: {"ts": "2026-03-07T09:00:00Z"}
  ```
- heartbeat: 30초마다 전송 (연결 유지)
- 연결 해제: 클라이언트 disconnect 감지 시 정리

**알림 전달 방식**
- 방안 A (단순): SSE 연결에서 5초마다 DB 폴링 → 새 알림 있으면 전송
- 방안 B (효율): in-memory 큐 (asyncio.Queue per user) → 알림 생성 시 큐에 push
- 1차 구현: **방안 A** (DB 폴링, 5초 간격) — 구현 단순, 사용자 수 적을 때 충분
- 추후 사용자 증가 시 방안 B로 전환

#### 4-3. 프론트엔드 — EventSource 연결

```javascript
// SSE 연결
```

### #7. 읽음 표시 (댓글/알림)

#### 7-1. 개요
- 목표: 댓글을 상대방이 확인했는지 표시 → "이거 봤어?" 질문 제거
- 알림 읽음은 기존 `is_read` 활용, 댓글 읽음은 신규

#### 7-2. DB 모델 — `comment_reads` 테이블

```sql
CREATE TABLE comment_reads (
    id INTEGER PRIMARY KEY,
    comment_id INTEGER NOT NULL REFERENCES comments(id) ON DELETE CASCADE,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    read_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(comment_id, user_id)
);
CREATE INDEX ix_comment_reads_comment ON comment_reads(comment_id);
```

#### 7-3. 백엔드 API

| 동작 | API | 설명 |
|------|-----|------|
| 읽음 처리 | `POST /projects/{pid}/comments/{cid}/read` | 해당 댓글을 읽음 처리 |
| 읽음 정보 조회 | 기존 댓글 목록 API 응답에 `read_count`, `is_read_by_me` 추가 | |

**댓글 목록 응답 확장**
```json
{
    "id": 1,
    "content": "...",
    "user_name": "홍길동",
    "read_count": 3,
    "is_read_by_me": true,
    "created_at": "..."
}
```

#### 7-4. 프론트엔드 UI

**댓글 읽음 표시**
```
| 홍길동  09:30                                        |
| 수정사항 반영했습니다.                                 |
|                                    읽음 3명  ✓✓     |
```

- 읽음 수: "읽음 N명" 텍스트 (댓글 우하단)
- 읽음 수 클릭 시: 읽은 사람 이름 목록 팝오버
- 본인 댓글: "읽음 N명" 표시
- 타인 댓글: 화면에 보이면 자동 읽음 처리 (IntersectionObserver)

**자동 읽음 처리**
- 댓글이 뷰포트에 1초 이상 노출되면 `POST .../read` 호출
- 이미 읽은 댓글은 재호출 안 함 (`is_read_by_me` 체크)
- 배치 처리: 여러 댓글이 동시에 보이면 개별 API 호출 (디바운스 500ms)

#### 7-5. 예외 처리
- 본인 댓글은 자동으로 읽음 처리 (API 호출 불필요)
- 삭제된 댓글의 읽음 데이터: CASCADE 삭제
- 팀원이 아닌 사용자의 읽음 시도: 403

### #14. 구글 로그인 (Google OAuth)

#### 14-1. 개요
- 목표: 원클릭 로그인으로 시스템 사용 허들 감소
- 현황: Google OAuth 인프라 이미 존재 (`auth.py`에 `google_login`, `google_callback`)
- 필요 작업: 프론트 로그인 버튼 추가 + 기존 계정 연동 로직

#### 14-2. 현재 구현 분석
- `GET /auth/login/google` → Google OAuth 페이지로 리다이렉트
- `GET /auth/callback/google` → 콜백, 사용자 생성/로그인, 세션 생성
- 이미 동작하는 상태, **프론트에 버튼만 추가하면 됨**

#### 14-3. 프론트엔드 — 로그인 화면

```
+-------------------------------+
|        Contract Sync          |
+-------------------------------+
| 이메일                        |
| [                           ] |
| 비밀번호                      |
| [                           ] |
|                               |
| [      로그인      ]          |
|                               |
| ──────── 또는 ────────        |
|                               |
| [G  Google로 로그인  ]        |
|                               |
| 계정이 없으신가요? 회원가입    |
+-------------------------------+
```

**Google 버튼 스타일**
- 흰 배경, 검정 테두리, Google 로고 아이콘
- 클릭 시: `window.location.href = '/auth/login/google'`

#### 14-4. 기존 계정과 Google 연동

**시나리오**
1. Google 로그인 시 같은 이메일의 기존 계정이 있으면 → 자동 연동 (현재 구현됨)
2. 설정 페이지에서 Google 계정 연동/해제 → 추후 #15(설정 확장)에서 구현

**DB 변경**
- 현재 `auth_provider` 필드로 구분 가능
- `google_id` 컬럼 추가는 선택 (현재는 email 매칭으로 충분)
- 1차 구현에서는 DB 변경 없이 프론트 버튼만 추가

#### 14-5. 예외 처리
- Google OAuth 설정 안 됨: 버튼 숨김 (서버에서 google_client_id 체크)
- OAuth 에러: "Google 로그인에 실패했습니다" 메시지와 함께 로그인 페이지로

### #16. 비밀번호 변경

#### 16-1. 백엔드 API

```
PATCH /auth/password
```

**요청**
```json
{
    "current_password": "현재비밀번호",
    "new_password": "새비밀번호",
    "new_password_confirm": "새비밀번호"
}
```

**검증**
- 현재 비밀번호 일치 확인
- 새 비밀번호 8자 이상, 영문+숫자 포함
- 새 비밀번호와 확인 일치
- Google 전용 계정(password_hash=null): "Google 로그인 계정은 비밀번호를 설정할 수 없습니다"

**응답**
- 성공: `{ "message": "비밀번호가 변경되었습니다." }`
- 실패: 400/401 에러
